# Privacy Policy

AgentBoard is a browser extension that connects your browser to AI and Model Context Protocol (MCP) services that you configure. This policy distinguishes data kept by the extension from data sent to those third parties.

## AgentBoard-operated services

AgentBoard does not operate an AI proxy, analytics service, telemetry collector, advertising service, or remote configuration service. The extension does not send usage data to an AgentBoard-owned server.

This does not mean all processing stays on your device. AI, MCP, URL-fetch, and user-script features communicate with endpoints described below.

## Data stored locally

AgentBoard stores configuration in `chrome.storage.local`, including:

- Agent names, descriptive provider metadata, explicit Connection API selection, model identifiers, endpoint URLs, API credentials, system prompts, and generation settings
- MCP server URLs and authorization tokens
- User-defined WebMCP scripts and built-in tool settings
- Slash commands, interface preferences, and logging level

AgentBoard also keeps tab-binding identifiers and timestamps in `chrome.storage.session` so a side panel remains attached to the correct tab during the browser session.

Conversation messages, attachments, reasoning, tool arguments, tool results, provider requests, provider responses, and provider errors are not written to extension storage by AgentBoard. They remain in memory for the active extension session and are lost when that context is destroyed.

AgentBoard's application logger and isolated-world relay diagnostics emit fixed event labels and discard caller-supplied context. Generated MAIN-world page-tool registration wrappers run outside that logger boundary and may include a browser- or page-thrown registration error in DevTools. Browser, provider SDK, website, and user-script code can also emit their own console output. AgentBoard does not transmit these console logs to an AgentBoard-operated service, but DevTools output should not be treated as a secret store.

## Data sent to configured AI endpoints

When you send a message or run Test Connection, AgentBoard sends a request directly from the extension to the endpoint configured for that agent. Depending on the action and enabled features, that request can include:

- Your system prompt, conversation messages, and attachments
- The attached tab's full URL and title, which AgentBoard automatically prepends when you send a chat message; URLs can contain sensitive paths, query parameters, fragments, document identifiers, or tokens
- MCP server instructions and available AI/MCP/WebMCP tool names, descriptions, and input schemas
- Tool calls and arguments generated by the model
- Tool results, including current-page or fetched-page content, returned to the model during a tool-enabled request
- Model and generation settings required by the selected Connection API

The endpoint can be a provider directly or a proxy/gateway selected by you. The descriptive provider label does not determine the network destination or protocol. The explicit Connection API does.

OpenAI Responses requests include `store: false`. That setting disables OpenAI Responses application-state storage for the request; it is not a promise of zero logging, zero data retention, Zero Data Retention eligibility, or disabled prompt caching by OpenAI or by an intervening proxy. Other supported protocols do not receive an equivalent OpenAI-specific flag.

Your endpoint operator's terms, retention, abuse-monitoring, caching, and privacy policies apply to data sent there. AgentBoard cannot inspect or control those practices.

## Data sent to MCP servers and websites

When remote MCP is enabled, AgentBoard connects directly to each configured MCP URL and may send its authorization token, protocol messages, tool names, and tool arguments. MCP responses and server instructions may subsequently be included in requests to the selected AI endpoint.

The built-in URL-fetch tool makes direct requests to URLs selected through tool use. It always omits browser cookies and authentication state; authenticated URL fetching is not supported. Websites still receive ordinary network information such as your IP address and request headers.

The default-enabled navigation system tool can navigate the attached tab. This is an ordinary browser navigation in that tab's existing context, so the destination can receive cookies, authentication state, referrer information, and other data the browser normally sends for that session. This differs from the credential-free URL-fetch tool.

The page-reading and WebMCP tools can read content from the active page; tool output may be shown in the sidebar and sent to the configured AI endpoint as part of the active request.

The built-in YouTube transcript tool sends the current video ID and a YouTube API key extracted from the page to YouTube's Innertube endpoint. Because that request runs on YouTube, it can include same-origin YouTube session credentials; the subsequent caption request explicitly includes the browser's YouTube/Google session credentials. YouTube and its caption-serving domains receive those requests under their own privacy and retention policies.

User-defined WebMCP scripts run with the capabilities described by their source and matching rules. Review scripts before enabling them. A script may read page data or contact third-party services independently of AgentBoard's built-in network paths.

## Backups and exports

A settings export is a plaintext JSON backup. It can contain AI API credentials, custom endpoints, model identifiers, system prompts, MCP authorization tokens, user scripts, and commands. Backups are not encrypted by AgentBoard. Store and share them as secrets.

Import validates the complete backup before applying it, but importing does not verify the trustworthiness of endpoints or user scripts contained in that backup.

## Permissions

AgentBoard requests broad host access so user-configured AI/MCP endpoints, built-in URL fetching, page tools, and WebMCP integrations can work across sites. Side-panel, scripting, storage, tab, navigation, and related permissions support those features. Browser-store permission prompts are a capability boundary, not evidence that every page is automatically read or transmitted. When you send a chat, however, AgentBoard does automatically transmit the attached tab's URL and title as described above.

## Deletion and control

You can edit or delete agents, MCP servers, scripts, and commands from Settings. Clearing the extension's site data or uninstalling the extension removes its local browser storage according to your browser's behavior. Exported backup files and data already received by third-party endpoints are separate; delete those through the relevant file system, provider, proxy, MCP server, or website.
